# Mini-Courier Planner

A Python capstone prototype that combines parcel sorting, 0/1 Knapsack Dynamic Programming, Dijkstra shortest paths, and a Nearest-Neighbor TSP approximation. It also measures runtime on increasing synthetic input sizes.

## Requirements

- Python 3.10 or newer
- Jupyter Notebook
- pandas
- matplotlib

## Run the project

1. Download or clone this repository and open a terminal in the `mini-courier-planner` folder.
2. Create and activate a virtual environment (recommended):

   ```bash
   python -m venv .venv
   ```

   Windows PowerShell:

   ```powershell
   .venv\Scripts\Activate.ps1
   ```

   macOS/Linux:

   ```bash
   source .venv/bin/activate
   ```

3. Install dependencies:

   ```bash
   python -m pip install -r requirements.txt
   ```

4. **Run in VS Code (recommended):** open the project folder in VS Code, open `mini_courier_planner.ipynb`, choose the `.venv` Python environment as the notebook kernel, and click **Run All**. If VS Code asks for `ipykernel`, it is included in `requirements.txt`.

   Alternatively, launch the browser notebook with:

   ```bash
   jupyter notebook mini_courier_planner.ipynb
   ```

5. Wait for every cell to finish. The notebook prints the sample solution, runs correctness checks, benchmarks each algorithm, and saves `images/runtime_comparison.png` and `images/runtime_measurements.csv`. The `images/screenshots/` folder contains the included VS Code evidence captures; those images are provided with the project and are not generated by the notebook.

No API key, external service, database, or GPU is required.

## Input data rules

- `parcels.csv`: `parcel_id`, `destination`, integer `weight`, integer `value`, integer `priority`, and `deadline` in `HH:MM` format.
- Lower numeric priority means higher priority. The display order is priority ascending, then deadline ascending, then parcel ID.
- Knapsack maximizes total parcel value while keeping total weight at or below the vehicle capacity. Priority order and value optimization are separate decisions in this prototype.
- `routes.csv`: undirected road edges; `distance` is a positive edge weight. `Depot` is the starting and ending location.
- The demonstration vehicle capacity is 12 weight units. Change `VEHICLE_CAPACITY` in the notebook to test another capacity.

## Algorithms and complexity

| Component | Method | Time complexity | Space complexity |
|---|---|---|---|
| Parcel ordering | Comparison sort | `O(n log n)` | `O(n)` for the sorted result |
| Packing | 0/1 Knapsack DP table | `O(nW)` | `O(nW)` |
| Individual shortest paths | Dijkstra with a binary heap and adjacency list | `O((V + E) log V)` | `O(V + E)` |
| Overall delivery order | Nearest-neighbor TSP approximation using shortest-path distances | Up to `O((K + 1)(V + E) log V)` for this implementation | `O(V + E + K)` excluding stored DP tables |

Here, `n` is the parcel count, `W` is integer vehicle capacity, `V` is the number of graph vertices, `E` is the number of road edges, and `K` is the number of distinct selected delivery destinations. The nearest-neighbor route is an approximation, not a guaranteed globally optimal TSP tour.
